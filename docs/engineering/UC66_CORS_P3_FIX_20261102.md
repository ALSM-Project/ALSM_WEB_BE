# ALSMV2-1050 — P3 CORS control-character correction

The original unrestricted-origin P2 correction is preserved. This delivery does

## Exact correction

The only production TypeScript change is the existing pre-URL guard in
`src/config/cors-policy.ts`: its character class now rejects ASCII C0
U+0000–U+001F and DEL U+007F as well as whitespace, before `new URL()` can remove
controls. The targeted ESLint comment documents the intentional control-byte range.
There is no new parser, fallback, dependency or trust rule.

Configuration entries still undergo their documented explicit surrounding
whitespace trim. Remaining non-whitespace controls at boundaries and all controls
inside an entry invalidate the entire configuration, including mixed lists.
Incoming Origin callback values are not trimmed and reject every control byte.
Joi and the production factory already share this parser, so no change to
`environment.validation.ts` or `main.ts` is needed. Case/host/default-port/IDN
normalization, exact tuple matching, explicit development access, credentials,
Authorization preflight and no-Origin API routing remain unchanged. There is no
implicit loopback/private-network or wildcard allowance.
