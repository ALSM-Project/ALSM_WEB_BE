# ALSM / UC66-05B — existing P2 CORS origin policy correction

Frontend remains unchanged at `6f9be0a`. No production registration or operational
activation is included.

## Root cause and correction

The production bootstrap's Origin callback returned true even after an Origin
failed its configured/loopback checks. It also implicitly trusted arbitrary
localhost/127.0.0.1 ports. With credentials enabled, the middleware reflected
unapproved Origins. This did not demonstrate a JWT/session authentication bypass.

`src/config/cors-policy.ts` now owns a small shared explicit-origin parser and the
production CORS options. `src/main.ts` installs those options. Configuration must
contain a nonempty comma-separated list of HTTP(S) origins with a hostname and
optional valid port. Paths (including a trailing slash), query/fragment, userinfo,
wildcards, opaque origins, backslashes, encoded hosts and malformed/empty entries
are rejected. A mixed valid/invalid list fails entirely. Surrounding configuration
whitespace is trimmed; URL normalization handles scheme/host case, IDN names and
default ports; duplicates collapse. Matching uses the exact normalized origin
tuple, never deceptive hostname prefixes/suffixes or implicit private-network trust.

The environment Joi schema invokes the same parser, rejecting bad configuration
at startup; the factory independently rejects it if startup validation is bypassed.
No environment has an allow-all or implicit loopback fallback. Operators choose
each environment's actual permitted origins explicitly.

Approved responses retain credentials and the installed middleware's existing
methods/header handling, including Authorization and Content-Type preflight.
Unapproved/malformed Origins receive no Access-Control-Allow-Origin or
Access-Control-Allow-Credentials. A missing Origin also receives no CORS grant,
while normal API routing/authentication remains available. Same-origin requests do
not need cross-origin permission. CORS denial does not itself block non-browser
HTTP clients or replace JWT/session/RBAC/CSRF protections; an otherwise authorized
request can reach a handler without receiving browser CORS response permission.
